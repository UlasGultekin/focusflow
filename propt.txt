Mevcut yapıyı tamamen koruyarak, istediğin ayrımı sağlayacak bir mimari güncellemesi öneriyorum. Temel prensip: **Bug, Teknik Borç, Snippet gibi varlıklar kendi tablolarında yaşar; görev ya da takvim öğesi olmaları isteğe bağlıdır.** Yani hiçbir şey otomatik olarak görev panosuna düşmez; yalnızca sen “Görev olarak ata” dediğinde göreve dönüşür.

## 🔄 Mimari Revizyon Özeti

| Varlık | Kendi Tablosu | Görev Olarak Atanabilir mi? | Takvime Eklenebilir mi? |
|--------|---------------|----------------------------|--------------------------|
| Görev | `tasks` | *(zaten görev)* | Evet, `planned_date` ile |
| Teknik Borç | `tech_debts` | ✅ “Göreve Dönüştür” butonu | ✅ `planned_date` ile (kendi alanı) |
| Bug | `bugs` | ✅ “Göreve Dönüştür” butonu | ✅ `planned_date` ile (kendi alanı) |
| Kod Snippet | `code_snippets` | ❌ (görevle ilişkilendirilebilir) | ❌ |
| Derin Çalışma Girişi | `deep_work_entries` | ❌ (göreve bağlı) | ❌ |

- **Görevler** hâlâ `tasks` tablosunda. Board, Todo/In Progress/Done yalnızca `tasks` üzerinde çalışır.
- **Bug ve Teknik Borç** kendi özel tablolarında tutulur. Onları yönettiğin ayrı paneller vardır (Dashboard widget’ları veya özel sayfalar).
- Bir Bug veya Teknik Borcu **“Göreve Dönüştür”** dediğinde, `tasks` tablosuna bir kopya oluşturulur ve aralarında bağlantı (`task_id` referansı) kurulur. Böylece board’a düşer.
- Takvim yalnızca `planned_date` içeren kayıtları gösterir. Bug ve Teknik Borç tablolarına da `planned_date` eklenir, böylece onları isteğe bağlı takvime yerleştirebilirsin.

## Görev 27: Merkezi Olmayan Varlık Yönetimi ve İsteğe Bağlı Bağlama

**Amaç:** Teknik Borç, Bug, Snippet gibi özel varlıkların görevlerden bağımsız olarak kendi tablolarında yönetilmesi; yalnızca kullanıcı istediğinde göreve dönüştürülmesi veya takvime eklenmesi.

### 27.1 Veritabanı Revizyonu

Aşağıdaki tablolar **Görev 21 ve 23’ün yerine geçecek** şekilde oluşturulur:

```sql
-- Teknik Borçlar (tasks'tan bağımsız)
CREATE TABLE IF NOT EXISTS tech_debts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  description TEXT,
  category TEXT DEFAULT 'refactor',  -- refactor, performance, security, cleanup, documentation
  estimated_minutes INTEGER,
  status TEXT DEFAULT 'open',        -- open, in_progress, resolved, archived
  priority TEXT DEFAULT 'medium',    -- low, medium, high, critical
  planned_date TEXT,                 -- isteğe bağlı takvim planlaması
  task_id INTEGER,                   -- dönüştürüldüğünde bağlanacak görev ID'si
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now')),
  FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE SET NULL
);

-- Bug'lar (tasks'tan bağımsız)
CREATE TABLE IF NOT EXISTS bugs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  description TEXT,
  severity TEXT DEFAULT 'minor',     -- critical, major, minor, trivial
  reproduction_steps TEXT,
  environment TEXT,
  status TEXT DEFAULT 'open',        -- open, in_progress, resolved, closed
  priority TEXT DEFAULT 'medium',
  planned_date TEXT,                 -- isteğe bağlı takvim planlaması
  fix_commit TEXT,
  task_id INTEGER,                   -- dönüştürüldüğünde bağlanacak görev ID'si
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now')),
  FOREIGN KEY (task_id) REFERENCES tasks(id) ON DELETE SET NULL
);
```

**Not:** `code_snippets` ve `deep_work_entries` tabloları aynen kalır, onlar zaten görevle ilişkilendirilebilir yapıdadır.

### 27.2 IPC Metodları (Yeni ve Güncellenen)

**Teknik Borç:**
- `addTechDebt(data)` → Yeni borç ekler.
- `updateTechDebt(id, data)` → Günceller.
- `deleteTechDebt(id)` → Siler.
- `convertTechDebtToTask(techDebtId)` → **Göreve dönüştürme**:
  - `tech_debts` kaydını okur.
  - `tasks` tablosuna yeni bir görev ekler (`task_type: 'tech_debt'`, başlık, açıklama, tahmini süre vb. kopyalanır).
  - `tech_debts` kaydının `task_id` alanını yeni görevin ID’si ile günceller.
  - Oluşan görev ID’sini döndürür.
- `getTechDebts(filters?)` → Liste. Filtreler: status, category, priority, planned_date aralığı.

**Bug:**
- `addBug(data)`, `updateBug(id, data)`, `deleteBug(id)`.
- `convertBugToTask(bugId)` → Yukarıdakiyle aynı mantık, `task_type: 'bug'`.
- `getBugs(filters?)`.

**Takvim Entegrasyonu için Ortak Metot:**
- `getCalendarItems(startDate, endDate)` → Birleştirilmiş liste döndürür:
  - `tasks` tablosundan `planned_date` dolu olan ve verilen aralıktaki görevler.
  - `tech_debts` tablosundan `planned_date` dolu kayıtlar.
  - `bugs` tablosundan `planned_date` dolu kayıtlar.
  - Her kayıt `{ type: 'task'|'tech_debt'|'bug', id, title, planned_date, planned_start_time, color, status }` formatında.

### 27.3 Görev ve Board Entegrasyonu

- **Board** (Görev 12) yalnızca `tasks` tablosundaki kayıtları gösterir. `task_type` bilgisine göre görsel farklılık (bug → kırmızı ikon, tech_debt → turuncu) korunur.
- **Yeni görev oluşturma** modalinde sadece “Görev” ve “Etkinlik” seçenekleri olur. Bug veya Teknik Borç eklemek isteyen kullanıcı, Dashboard’daki ilgili widget üzerinden veya ana menüdeki “Bug’lar” / “Teknik Borçlar” sayfasından ekler.
- Bir Bug veya Teknik Borcu göreve dönüştürme: İlgili panelde her kaydın yanında **“Göreve Dönüştür”** butonu bulunur. Tıklandığında, oluşan görev Board’a düşer.

### 27.4 Takvim Entegrasyonu

- Takvim (Görev 13) `getCalendarItems` metodunu kullanır.
- Bir Bug veya Teknik Borcu takvimde göstermek için: İlgili varlığın detayında bir **“Takvime Ekle”** butonu bulunur. Tıklandığında `planned_date` alanı seçilir (mini bir tarih/saat seçici ile). Bu alan doldurulduğu anda takvimde görünür.
- Takvimden kaldırmak için `planned_date` null yapılır.

### 27.5 Dashboard Güncellemesi

Widget’lar güncellenir:
- **“Açık Bug’lar”** widget’ı doğrudan `bugs` tablosundan okur.
- **“Teknik Borç Özeti”** widget’ı doğrudan `tech_debts` tablosundan okur.
- İsteğe bağlı olarak her iki widget’ta da “Yeni Ekle” butonu bulunur.

### 27.6 Eski Yapıdan Geçiş (Migrasyon)

- Daha önce `tasks` tablosuna `task_type` olarak `bug` veya `tech_debt` eklenmiş olabilir. Bunlar için bir kerelik migrasyon script’i çalıştırılır: `task_type = 'bug'` olanlar `bugs` tablosuna, `'tech_debt'` olanlar `tech_debts` tablosuna kopyalanır ve `task_id` ile bağlanır. Ardından `tasks` tablosundaki `task_type` değerleri `'task'` olarak güncellenir (opsiyonel). Bu sayede veri kaybı olmaz.
